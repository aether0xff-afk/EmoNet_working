# 5. EmoNet의 구조

## 5.1 전체 구조

### 가. 기본 개념

EmoNet은 에피소드를 입력으로 받아, 그 입력이 내부 신경망을 통과하며 어떤 감정 흐름을 형성하는지를 계산하고 기록하는 구조이다. 여기서 감정은 최종 라벨이나 응답 문장으로 바로 정의되지 않는다. EmoNet은 입력 자극이 노드들을 어떻게 활성화하고, 그 활성 흐름이 시간에 따라 어떻게 이어지며, 어떤 branch가 최종 내부 상태를 대표하게 되는지를 추적한다.

### 나. 구성 단계

EmoNet의 구조는 입력부, 신경망 처리부, 기록부, 해석부로 나눌 수 있다.

| 구분 | 구성 요소 | 역할 |
|---|---|---|
| 입력부 | episode, stim_vec | 감정 흐름을 유발하는 상황을 자극 벡터로 변환 |
| 신경망 처리부 | node, threshold, memory, signal propagation | 자극을 내부 네트워크에서 확산, 억제, 유지 |
| 기록부 | trace | tick별 내부 활성 상태를 시계열로 저장 |
| 구조화부 | branch, dominant branch | trace 안의 주요 활성 경로를 추출 |
| 해석부 | emotion axis, cluster path, semantic report | 내부 경로를 감정적으로 해석 가능한 형태로 정리 |

### 다. 전체 흐름

EmoNet의 전체 흐름은 그림 5-1과 같이 정리할 수 있다.

```text
episode
-> stim_vec
-> node activation
-> signal propagation
-> trace
-> branch
-> dominant branch
-> cluster path
-> semantic report
```

이 흐름에서 episode는 감정 상태를 유발하는 외부 상황 단위이고, stim_vec는 episode에서 추출된 4차원 자극 벡터이다. node activation은 자극 벡터와 노드 내부 상태를 바탕으로 각 노드가 활성화되는 과정이며, signal propagation은 활성화된 노드가 연결된 다른 노드로 신호를 전달하는 과정이다. 이 과정이 tick 단위로 반복되면서 trace가 형성된다.

> 프롬프트 파일: `figure_prompts/fig_5_1_overall_architecture.txt`

## 5.2 입력부

### 가. 입력부의 역할

입력부는 외부 에피소드를 EmoNet 내부에서 계산 가능한 자극 형태로 바꾸는 단계이다. 이 단계의 핵심은 입력 문장을 단일 감정 라벨로 바꾸는 것이 아니라, 감정 흐름을 유발할 수 있는 복합 자극 벡터로 변환하는 데 있다.

| 입력부 요소 | 설명 |
|---|---|
| episode | 감정 상태를 유발하는 사건 단위 |
| 감정 단서 | episode 안에 포함된 위협, 손실, 부당함, 관계 불안 등 |
| stim_vec | 감정 단서를 4차원 수치 자극으로 변환한 벡터 |
| 혼합 자극 | 여러 감정 단서가 동시에 반영된 입력 상태 |

### 나. episode에서 stim_vec로의 변환

하나의 episode는 여러 감정 단서를 동시에 포함한다. 예를 들어 공개적 무시 상황은 부정 정서, 사회적 위협, 부당함 판단, 관계 손상 가능성, 반격 충동, 표현 억제 가능성을 함께 포함할 수 있다. 입력부는 이러한 단서들을 추출하여 4차원 stim_vec로 변환한다.

> 그림 5-2. episode에서 stim_vec로의 변환  
> 프롬프트 파일: `figure_prompts/fig_5_2_episode_to_stim_vec.txt`

### 다. 입력부의 구조적 의미

입력부에서 만들어진 stim_vec는 이후 모든 내부 전파의 출발점이다. 다만 이 벡터는 모든 노드에 동일하게 작용하지 않는다. 각 노드는 자신의 고유 성향과 민감도에 따라 stim_vec의 일부 차원에 더 강하게 반응하며, 이 차이가 이후 branch 분기의 기반이 된다.

## 5.3 신경망 처리부

### 가. 신경망 처리부의 역할

신경망 처리부는 stim_vec가 256개의 노드를 통과하며 활성 흐름을 만드는 단계이다. 이 단계에서는 입력 자극, 노드의 고유 성향, 역치, 기억, 피로도, 연결 입력이 함께 작용하여 각 tick의 활성 상태가 결정된다.

### 나. 노드 구성

| 노드 종류 | 개수 | 비율 | 역할 | 의미 |
|---|---:|---:|---|---|
| Excitatory | 115개 | 44.9% | 자극 반응을 강화하고 확산 | 특정 감정 방향이 더 뚜렷하게 드러나도록 활성 흐름을 증폭 |
| Inhibitory | 115개 | 44.9% | 과도한 반응을 억제하고 완충 | 감정 반응이 한쪽으로 지나치게 치우치지 않도록 조절 |
| Modulatory | 26개 | 10.2% | 전체 네트워크의 민감도 조절 | 역치, 기억, dropout 등 전역 상태를 조절 |

### 다. 노드 내부 상태

| 내부 상태 | 의미 | 역할 |
|---|---|---|
| 활성값 K | 노드의 현재 반응 강도 | 역치를 넘으면 노드가 활성화됨 |
| stim_vec | 노드가 처리하는 자극 정보 | 어떤 감정 방향의 자극을 처리 중인지 나타냄 |
| intrinsic_bias | 노드가 기본적으로 잘 반응하는 자극 방향 | 특정 자극 축에 민감하게 반응하도록 함 |
| threshold | 노드가 활성화되기 위한 임계값 | K와 비교하여 활성화 여부를 결정 |
| memory | 이전 활성의 잔류 정보 | 유사 자극이 다시 들어왔을 때 현재 반응에 영향 |
| fatigue | 반복 활성화에 따른 반응 저하 | 과도한 반복 활성 억제 |
| recent_activity | 최근 tick의 활성 이력 | 단기적 활성 패턴 반영 |
| refractory_left | 활성화 직후 다시 켜지지 않는 기간 | 과도한 연속 활성 방지 |
| neighbors | 연결된 다른 노드 정보 | 신호 전달 경로 형성 |

### 라. 한 tick에서 일어나는 일

한 tick에서는 현재 stim_vec, 이전 기억, 연결 노드 입력, 피로도와 억제 효과가 결합되어 활성 후보값 K가 계산된다. 이후 K가 threshold를 넘으면 노드가 활성화되고, 연결된 후속 노드로 신호를 전달한다. 넘지 못한 노드는 약화되거나 비활성 상태로 남는다.

```text
stim_vec + memory + 연결 입력 - fatigue/억제
-> K 계산
-> threshold 비교
-> 활성화 또는 비활성
-> 다음 노드로 신호 전달
```

> 프롬프트 파일: `figure_prompts/fig_5_3_one_tick_activation.txt`

## 5.4 기록부

### 가. trace의 위치

기록부는 신경망 처리부에서 발생한 tick별 내부 상태를 trace로 저장하는 단계이다. trace는 단일 시점의 활성 스냅샷이 아니라, 입력 이후 내부 상태가 시간에 따라 어떻게 변화했는지를 담은 시계열 기록이다.

### 나. trace가 담는 정보

| 정보 종류 | 설명 |
|---|---|
| 시간 정보 | tick에 따라 내부 상태가 어떻게 변했는지 |
| 활성 정보 | 각 tick에서 어떤 노드가 켜졌는지 |
| 강도 정보 | 활성값 K가 얼마나 강했는지 |
| 지속 정보 | 특정 활성이나 흐름이 얼마나 오래 유지되었는지 |
| 경로 정보 | 활성화된 노드들이 어떤 순서로 이어졌는지 |
| branch 정보 | 어떤 branch가 생겼고 어떤 branch가 유지되었는지 |
| 자극 벡터 정보 | tick별로 변형되거나 반영된 stim_vec 상태 |

### 다. 시계열 구조

trace는 다음과 같은 형태의 시간 순서 기록으로 볼 수 있다.

```text
trace = [t0 상태, t1 상태, t2 상태, ..., tT 상태]
```

이 구조 때문에 trace는 감정이 한순간에 결정되는 것이 아니라, 시간에 따라 형성되고 유지되며 약화되는 과정임을 보여준다.

> 그림 5-4. trace의 시계열 구조  
> 프롬프트 파일: `figure_prompts/fig_5_4_trace_timeseries.txt`

## 5.5 branch 구조

### 가. branch의 위치

branch는 trace 안에서 특정 방향으로 이어진 내부 활성 경로이다. trace가 전체 시계열 기록이라면, branch는 그 안에서 특정 감정 해석 또는 행동 준비 방향으로 연결된 부분 경로이다.

### 나. branch의 종류

| branch 종류 | 의미 |
|---|---|
| active branch | raw trace 안에서 실제로 활성화된 경로 |
| weak branch | 활성은 되었지만 강도나 지속성이 낮은 경로 |
| dropped branch | 중간에 약해지거나 끊겨 최종 흐름에서 탈락한 경로 |
| competing branch | dominant branch와 동시에 경쟁한 다른 경로 |
| dominant branch | 최종 내부 상태를 가장 잘 대표하는 경로 |
| residual branch | dominant는 아니지만 후반부에 약하게 남은 경로 |

### 다. dominant branch 결정 기준

| 기준 | 의미 | dominant branch에서 중요한 이유 |
|---|---|---|
| 활성 강도 | 경로에 포함된 노드들이 얼마나 강하게 켜졌는가 | 강하게 반응한 경로일수록 핵심 내부 반응일 가능성이 높음 |
| 지속성 | branch가 여러 tick 동안 얼마나 오래 유지되었는가 | 오래 유지된 흐름이 감정 상태를 더 잘 대표함 |
| 연결성 | 노드들이 끊기지 않고 하나의 경로로 이어졌는가 | 연속된 경로가 내부 전파 흐름을 더 잘 설명함 |
| 후반부 생존 | trace 후반 또는 응답 직전까지 살아남았는가 | 최종 내부 상태에 가까울 가능성이 큼 |
| 클러스터 통과 정보 | 어떤 기능/감정 cluster를 지나갔는가 | 의미 있는 내부 영역을 거쳤는지 확인 가능 |
| 감정축 일관성 | 노드/클러스터의 감정 방향이 일관적인가 | 하나의 감정 상태로 해석 가능한지 판단 |
| 최종 상태 관련성 | 최종 응답 또는 최종 내부 상태를 설명하는가 | dominant branch는 최종적으로 남은 흐름을 대표해야 함 |

### 라. branch 구조 그림

branch 구조는 여러 후보 경로 중 일부가 약화되고, 하나의 대표 경로가 dominant branch로 선택되는 방식으로 시각화하는 것이 좋다.

## 5.6 해석부

### 가. 해석부의 역할

해석부는 trace와 branch를 감정적으로 의미 있는 형태로 변환하는 단계이다. 이 단계에서는 감정축과 cluster를 기준으로 dominant branch가 어떤 내부 감정 흐름을 나타내는지 해석한다.

### 나. 감정축

| 감정축 | 의미 | 예시 |
|---|---|---|
| 감정가 축 | 정서의 기본 방향 | 긍정 / 부정 |
| 통제감 축 | 상황을 바꿀 수 있다고 느끼는 정도 | 통제 가능 / 무력감 |
| 사회적 방향 축 | 감정이 향하는 대상 | 자기 / 타인 / 관계 |
| 행동 경향 축 | 감정이 유도하는 행동 준비 | 접근 / 회피 / 반격 / 억제 |
| 표현-억제 축 | 감정을 드러내는지 억누르는지 | 표현 / 억제 |
| 책임 귀인 축 | 원인과 책임을 어디에 두는지 | 자기 책임 / 타인 책임 / 상황 책임 |

### 다. cluster

| 클러스터 종류 | 주요 기능 | 해석 예시 |
|---|---|---|
| 위협/손실 클러스터 | 위험, 모욕, 상실, 불안 단서 처리 | 상황을 위협으로 인식함 |
| 평가 클러스터 | 책임, 원인, 부당함, 통제 가능성 판단 | 상대의 행동을 부당하다고 평가함 |
| 통제감 클러스터 | 선택권, 가능성, 무력감 처리 | 상황을 바꿀 수 없다고 느낌 |
| 사회적 관계 클러스터 | 타인의 시선, 관계 손상, 소속감 처리 | 관계가 나빠질 가능성을 고려함 |
| 행동 경향 클러스터 | 접근, 회피, 반격, 억제 등 행동 준비 | 따지고 싶거나 피하고 싶어함 |
| 조절 클러스터 | 억제, 완화, 재평가, 안정화 | 충동을 조절하거나 반응을 완화함 |
| 기억/잔류 클러스터 | 이전 활성, 과거 경험, 지속 신호 반영 | 이전 감정 흐름이 현재 판단에 남아 있음 |

### 라. node path에서 cluster path로

cluster path는 branch가 통과한 cluster들의 순서를 나타낸다. 예를 들어 node path가 단순히 `n0 -> n3 -> n6 -> n10 -> n13`으로 표시될 경우, 이 경로만으로는 감정 의미를 해석하기 어렵다. 그러나 cluster path로 바꾸면 다음과 같이 읽을 수 있다.

```text
n0 -> n3 -> n6 -> n10 -> n13
= 위협 감지 -> 부당함 평가 -> 반격 충동 -> 표현 준비 -> 최종 상태
```

> 그림 5-6. node path에서 cluster path로 변환  
> 프롬프트 파일: `figure_prompts/fig_5_6_node_to_cluster_path.txt`

### 마. semantic report

semantic report는 trace, branch, dominant branch, cluster path, 감정축 정보를 바탕으로 생성되는 해석 보고이다. 이는 최종 응답 자체가 아니라, 응답 이전에 EmoNet 내부에서 어떤 감정 흐름이 형성되었는지를 설명하는 자료이다.

## 5.7 구조적 의의

### 가. 감정을 과정으로 다룸

EmoNet의 구조적 의의는 감정을 단일 라벨이나 문체 조건이 아니라, 내부 활성의 시간적 전개와 경로 선택의 결과로 다룬다는 데 있다. 감정은 입력에 붙는 이름이 아니라, 입력이 내부 네트워크를 통과하며 형성한 동역학적 흐름으로 이해된다.

### 나. 내부 상태의 관찰 가능성

EmoNet은 trace와 branch를 통해 내부 감정 상태가 어떤 경로로 형성되었는지를 관찰할 수 있게 한다. 이를 통해 어떤 감정으로 분류되었는가뿐 아니라, 그 감정이 어떤 내부 경로를 통해 형성되었는가를 설명할 수 있다.

### 다. 해석과 검증의 기반

EmoNet의 구조는 감정 상태를 해석하고 검증하기 위한 기반이 된다. trace가 감정축 구조를 포함하는지, branch가 의미 있는 감정 경로를 형성하는지, dominant branch가 최종 내부 상태를 대표하는지 확인함으로써 EmoNet의 감정 상태 표현 가능성을 평가할 수 있다.
