# z의 크기 변화 실험

## 실험 질문
잠재 감정 벡터 `z`의 차원 수는 감정 정보 보존, 스타일 예측, 계산 비용 사이에서 어떤 균형점을 갖는가.

## 비교 설정
1. `d_z = 32`
2. `d_z = 64`
3. `d_z = 128`

필요하면 `256`까지 확장할 수 있지만, 논문에서는 3개 정도만 비교해도 충분하다.

## 핵심 가설
1. 너무 작은 `z`는 감정 상태의 세부 정보를 잃는다.
2. 너무 큰 `z`는 잡음과 과적합을 늘릴 수 있다.
3. 중간 차원에서 가장 좋은 제어 가능성과 효율의 균형이 나타날 가능성이 높다.

## 추천 metric
1. `z -> s` validation MAE
2. style consistency score
3. latent separability
4. branch reconstruction or summary fidelity
5. inference latency
6. memory footprint

## 넣으면 좋은 그림
1. 차원별 성능 비교 선 그래프
2. 차원별 latency bar chart
3. 차원별 `z` 분포 UMAP
4. 차원별 human evaluation 평균 점수

## 해석 가이드
성능이 가장 높다고 무조건 최종 차원으로 고르는 것보다, latency와 안정성까지 함께 고려했다고 쓰는 편이 좋다. 예를 들어 `128`이 미세하게 좋더라도 계산 비용이 크고 human evaluation 차이가 거의 없다면 `64`를 최종 선택하는 논리가 더 설득력 있다.

## 본문에 바로 넣을 수 있는 문장
잠재벡터 크기의 영향을 분석하기 위해 `d_z`를 32, 64, 128로 변화시키며 비교 실험을 수행하였다. 그 결과 작은 차원은 감정 상태의 세부 차이를 충분히 보존하지 못했고, 큰 차원은 계산 비용 증가에 비해 성능 향상이 제한적이었다. 따라서 본 연구는 성능, 안정성, 계산 효율의 균형을 기준으로 최종 잠재 차원을 선택하였다.
